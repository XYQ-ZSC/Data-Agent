## 1. 背景与目标

Data-Agent 已具备可扩展的数据库插件体系、数据库工作台和 Agent SQL 工具。DM 插件已打通基础连接、部分元数据和数据操作，但要达到完整适配，还需要统一解决数据库方言、对象生命周期、事务边界、IDE 交互以及 Agent 执行治理。

本项目按六个阶段交付：① JDBC / Driver；② Metadata / DDL；③ SQL Language；④ Database IDE；⑤ Advanced SQL；⑥ Agent。六阶段是能力建设和验收划分，存在交叉依赖，不要求所有开发工作严格串行。

最终用户应能够完成以下闭环：创建 DM8 连接，浏览授权对象，编辑和验证 SQL，查询及修改数据，管理对象 DDL，分析执行计划，运行程序块，并通过 Agent 在授权范围内完成同等操作。

“完整适配”指本文定义且通过认证的能力集合，不表示支持 DM8 全部语法、全部兼容模式或全部管理命令。

### 1.1 用户与核心场景

| 用户 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 应用开发者 | 连接数据库、编辑 SQL、查看表结构、调整数据 | 不必手工绕过 Schema、标识符和类型差异 |
| 数据分析人员 | 查询数据、获取对象说明、使用 Agent 分析 | SQL 作用域明确，结果完整可解释，敏感信息不越权 |
| DBA / 数据库开发者 | 查看 DDL、管理约束与序列、运行过程、分析计划 | 操作后状态可验证，权限不足和数据库限制可定位 |
| 工作区管理员 | 管理连接权限与写操作授权 | 用户、工作区、连接、Schema 和操作之间有一致的权限边界 |
| 测试与运维人员 | 回归、定位失败、判断版本兼容性 | 有可复现测试夹具、认证矩阵及关联日志 |

### 1.2 范围边界

本轮覆盖 DM8 的常用关系数据库开发能力。核心对象包括 Schema、Table、View、Column、Index、Constraint、Function、Procedure、Trigger、Sequence。

以下暂不作为必达范围：数据库实例安装与集群运维、备份恢复、灾备切换、跨库数据迁移、全量存储管理、PL 调试器、Package / Type / 同义词等扩展对象的完整生命周期、全部专有或空间类型编辑。对超出范围的对象和语法，应明确提示能力边界。

跨 HTTP 请求的手动事务会话不作为本轮必达能力；提供单次执行事务和符合条件的批量事务。若未来支持手动事务，需另行设计会话固定连接、过期回滚和并发控制。

## 3. 总体架构与设计原则

### 3.1 组件职责

| 层级 | 现有落点 | 目标职责 |
| --- | --- | --- |
| 插件 SPI | `data-agent-server-plugin` | 声明能力、统一元数据和 SQL 分析结果，定义失败与不支持语义 |
| DM 适配层 | `data-agent-server-plugins/dm-plugin` | 封装 DM 驱动、字典查询、标识符、类型转换、SQL 方言及执行计划适配 |
| 应用服务层 | `data-agent-server-app` 中数据库服务 | 管理权限、连接池、执行生命周期、事务策略、取消和审计 |
| IDE | `Data-Agent-Client` | 呈现能力、对象与执行状态，编辑 SQL / DDL / 数据，显示诊断和计划 |
| Agent | `data-agent-server-app` 中 Agent 工具 | 获取受限上下文，分析执行意图，申请必要授权并使用统一执行入口 |

数据库差异应落在插件边界。前端、业务服务和 Agent 不应各自维护一套 DM 标识符规则或首关键词判断逻辑。新增 SPI 能力需要保持现有 MySQL 插件的兼容性。

### 3.2 关键架构决策

1. **能力显式声明。** 建议建立 capability descriptor，至少声明对象类型、DDL 操作、SQL 分析、程序块、计划、取消和事务模式；版本或权限不满足时返回明确原因。不能用空列表或空字符串同时表示“不支持”“无权限”和“确实没有对象”。
2. **Schema 是对象作用域。** DM 的占位 catalog 只用于兼容现有树形结构，不得作为 SQL 限定符泄漏到查询中。对象身份由连接、Schema、对象类型和数据库返回的原始名称共同确定。
3. **名称展示与解析分离。** 保存原始名称和是否引用等必要信息；关键词识别可规范化，实际对象访问不能无条件转换大小写。列表、搜索、DDL、数据编辑和 Agent 采用一致规则。
4. **SQL 分析共享。** 切分、诊断、对象提取、风险判定来自同一方言模块。优先支持经过认证的语法子集；无法分析时返回“不支持 / 未知”，不得默认验证通过。
5. **事务由执行上下文管理。** 应用服务决定事务模式，插件执行器服从该上下文，避免内外层重复提交。所有入口返回可区分的执行结果和提交结果。
6. **权限与审批分离。** 数据库权限是最终执行边界，应用权限限制工具可访问范围；审批只表达用户允许某项操作，不能提升数据库权限或跨工作区访问。
7. **结果与副作用分离。** 语句返回成功不一定等于事务已提交；请求超时不一定等于数据库已停止。界面、Agent 和日志必须使用真实可确认的状态。

### 3.3 阶段依赖

| 阶段 | 主要依赖 | 可并行工作 |
| --- | --- | --- |
| ① 基础接入 | 现有插件 SPI、驱动管理和权限框架 | 认证环境、类型测试夹具准备 |
| ② 元数据 | ① 连接、执行和 Schema 规则 | 与③共同定义对象身份和名称模型 |
| ③ 语言 | ① 数据库类型与执行边界 | 与②并行建设语法语料和分析模型 |
| ④ IDE | ①；对象能力依赖②，诊断依赖③ | 提前完成交互稿、能力开关和错误状态 |
| ⑤ 高级 SQL | ①事务执行、②对象模型、③切分及分析 | 计划界面、参数表单可提前设计 |
| ⑥ Agent | ①②③；高级调用依赖⑤ | 提前定义审批协议、上下文和离线评测 |

## 4. 第一阶段：JDBC / Driver

### 4.1 目标

用户能够稳定建立 DM8 连接、在正确的 Schema 中执行 SQL，并得到可解释的数据、错误和事务结果。

### 4.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM1-01 | 驱动发现、下载 / 上传、版本选择与动态加载 | P0 | 已认证驱动成功加载；缺失、损坏、不兼容和冲突有明确错误；日志不记录凭据 |
| DM1-02 | 连接测试、默认端口、可配置属性、连接超时与 Schema 初始化 | P0 | 正常连接可用；密码错误、网络异常、无效 Schema 可区分；初始化失败关闭物理连接 |
| DM1-03 | 连接池复用、隔离、校验、淘汰与恢复 | P0 | 不同用户 / 工作区权限边界不串用；不同 Schema 不串用；会话状态恢复失败时淘汰连接 |
| DM1-04 | SQL 执行、结果集、影响行数、错误码和多结果承载 | P0 | 返回原始 SQL、执行状态、耗时、列信息、消息及数据库错误；不将失败包装为空结果成功 |
| DM1-05 | 单次事务与批量 DML 事务 | P0 | 可事务化的批量 DML 失败即停止并回滚；标识已回滚、失败和未执行语句；提交失败不显示已提交 |
| DM1-06 | 类型读取与写入转换 | P0 | 数值精度、时间精度、时区、NULL、二进制和大对象满足认证矩阵；不支持编辑的类型显示只读原因 |
| DM1-07 | 执行超时、取消和结果集上限 | P1 | 参数可配置；超限返回明确标记；取消传播到 JDBC；无法确认停止时返回待确认状态 |

P0 为所属阶段发布阻断项；P1 为本轮六阶段完整交付必达项，可在阶段内分批交付。非目标能力不进入完成率分母。

### 4.3 事务契约

- 默认单次请求独立管理事务；不承诺不同请求复用同一物理连接。
- 批量原子模式仅接受已认证、可事务化且没有已知隐式提交或内部提交行为的语句集合。DDL、未知程序块和未确认副作用的调用不得直接宣称“全部可回滚”。
- 对 DDL / DML 混合脚本，提供逐语句执行模式并在执行前说明可能部分生效；或拒绝不满足条件的原子模式请求。
- 不支持的显式事务控制在执行前拒绝，包括已识别的提交、回滚、事务开启和自动提交设置；识别范围由第三阶段方言分析补齐。
- 提交或回滚响应丢失时标记结果未知，禁止自动重试可能已经生效的写操作。
- 连接归还前恢复自动提交、隔离级别、只读属性和 Schema 等应用允许变更的状态；无法可靠恢复时关闭连接。

### 4.4 类型认证矩阵

至少覆盖：整数边界、超出 JavaScript 安全整数范围的值、定点小数精度、浮点特殊值、字符与 Unicode、空字符串与 NULL、DATE / DATETIME / TIMESTAMP、带精度的时区类型、BIT / BOOLEAN、BINARY / VARBINARY、BLOB / CLOB。类型和语义是否可用以已认证实例配置为准，不能把某一种兼容模式的行为硬编码为全部 DM8 的行为。

每类测试应覆盖读取、序列化、界面显示；支持编辑的类型还需覆盖参数绑定、写回和重新读取。大对象应有预览上限和截断标记，禁止把截断预览当完整值写回。

### 4.5 阶段出口

驱动、连接池、SQL 和类型路径完成真实 DM8 集成测试；异常连接无泄漏；事务状态可核对；不存在数据损坏、越权或已知误提交问题。仅有连接测试成功不足以通过本阶段。

## 5. 第二阶段：Metadata / DDL

### 5.1 目标与对象范围

对象浏览与操作使用统一元数据契约，确保“能看到的对象可正确定位，支持的 DDL 可正确获取及执行”。对象创建、修改和删除均受权限与能力控制。

| 对象 | 最小元数据 | 必达操作 |
| --- | --- | --- |
| Schema | 原始名称、可见性、当前作用域 | 列表、切换；创建 / 删除 Schema 暂不纳入必达范围 |
| Table | 名称、注释、列、主键、索引及约束关联 | 搜索、详情、DDL、创建、修改、重命名、删除 |
| View | 名称、列、定义、注释（可获取时） | 搜索、详情、DDL、创建 / 修改、删除、查询 |
| Column | 顺序、类型、长度 / 精度、可空、默认值、注释、生成属性 | 列表、增删改；有依赖时返回数据库错误及对象信息 |
| Index | 类型、唯一性、有序列 / 表达式、约束关联 | 列表、DDL、创建、删除；不支持直接改名时禁用入口 |
| Constraint | PK、FK、UNIQUE、CHECK、所属列、引用对象、状态 | 列表、详情、DDL、创建、删除；状态变更按能力声明 |
| Function | 参数顺序、方向、类型、返回值、定义 | 列表、搜索、详情、DDL、创建 / 替换、删除 |
| Procedure | 参数顺序、方向、类型、定义 | 列表、搜索、详情、DDL、创建 / 替换、删除 |
| Trigger | 关联表、事件、时机、状态、定义 | 列表、详情、DDL、创建 / 替换、删除、可支持的启停 |
| Sequence | 增量、上下界、循环、缓存等可获取属性 | 列表、详情、DDL、创建、修改、删除；浏览不得调用 NEXTVAL |

数据库不支持某操作时，不得通过伪成功满足表格要求；应记录认证边界并在发布范围中明确排除。

### 5.2 功能要求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM2-01 | 统一对象身份、搜索、分页和刷新 | P0 | 同名跨 Schema、大小写敏感名、Unicode 和保留字对象不混淆 |
| DM2-02 | 获取完整对象 DDL | P0 | 保留必要定义；权限不足、扩展包不可用、对象不存在分别返回；降级重建必须注明可能缺失内容 |
| DM2-03 | 补齐约束与序列 SPI、DM 实现和服务接口 | P0 | 从插件到 API 可访问完整对象；复合外键按列序对应，避免重复计算约束背后的索引 |
| DM2-04 | 对象生命周期与缓存失效 | P0 | 修改成功后可重新读取真实状态；失败不提前刷新为成功；变更影响补全及 Agent 元数据缓存 |
| DM2-05 | 最小权限账户访问 | P0 | 能区分无对象与无权限，不要求用户必须使用 SYSDBA |
| DM2-06 | 字典差异和大量对象访问 | P1 | 已认证版本字典查询可用；分页、取消和错误可追踪，避免逐列查询造成无界 N+1 请求 |

### 5.3 阶段出口

为每类对象准备固定测试夹具；在独立测试 Schema 中验证支持的创建、查询、变更、DDL 获取和删除。DDL 在空白测试 Schema 中重建后比较语义结构，不能只断言文本非空。规范化比较应允许数据库生成的名称和格式差异。

## 6. 第三阶段：SQL Language

### 6.1 目标

提供 DM 方言分析服务，支撑 IDE 诊断、程序块执行、对象提取和 Agent 风险判断。使用 `plsql` 格式化器只代表格式化近似，不等于完成 DM 语法支持。

### 6.2 功能要求

| 编号 | 能力 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM3-01 | Lexer | P0 | 识别支持范围内的关键词、字符串、数字、参数、注释和引用标识符；保留字符偏移及行列 |
| DM3-02 | Parser | P0 | 覆盖常用 SELECT / CTE / JOIN / 子查询、DML、第二阶段对象 DDL、事务控制及第五阶段程序块语法 |
| DM3-03 | Visitor / 语义提取 | P0 | 区分真实表、别名和 CTE；输出读写对象、字段引用、调用及无法静态确定的引用 |
| DM3-04 | SQL Splitter | P0 | 字符串、双引号名称、注释内分号不切分；程序块内部语句不切分；分隔符不传给 JDBC |
| DM3-05 | Validator | P0 | 区分有效、语法错误、方言不支持和上下文无法确定；无效语句不能返回有效 |
| DM3-06 | Identifier | P0 | 引用、反引用、转义及限定名处理一致；展示原名，访问准确 |
| DM3-07 | 诊断与上下文绑定 | P1 | 给出可定位的错误范围；离线语法检查与依赖元数据的检查分别标识 |

语法实现方式在技术评审中选择，要求具有可维护语法源、可复现生成过程和扩展测试。可评估 ANTLR 等实现路径，但不应将已有 MySQL 或 Oracle 语法直接声明为 DM 完整语法。

### 6.3 建议分析结果契约

至少包含：方言版本、解析状态、语句范围、语句类型、诊断集合、读对象、写对象、调用对象、未知引用和副作用标记。对象记录保留 Schema、原始名称、引用状态和源位置。

动态 SQL、未解析调用和无法确定来源的对象必须保留为未知项；不得用空对象列表表达“没有副作用”。客户端只消费分析结果，服务器在执行前基于实际 SQL 重新分析。

### 6.4 切分规则与验收语料

第一版明确支持普通语句分号分隔、程序块独立 `/` 行结束，以及单个程序块在输入结尾结束。程序块后接普通 SQL 而没有受支持分隔符时，应诊断为边界不明确，不能静默吞并或猜测执行。其他客户端命令不默认作为 SQL 执行。

语料至少包含嵌套 BEGIN / END、IF / LOOP / CASE、异常块、过程 / 函数 / 触发器定义、多行注释、转义引号、包含分号的名称、LF / CRLF、空脚本、末尾无分号、未闭合字符串与注释、混合脚本。具体语法支持以认证语料清单为准。

阶段出口：全部必达语料的切分数量、原文范围、诊断与对象提取匹配预期；不支持语法有明确输出；不得出现已知写操作误判为安全只读的情况。

## 7. 第四阶段：Database IDE

### 7.1 目标

使用户在工作台完成对象发现、SQL 编写、DDL 修改、数据维护和关系浏览，且所有操作与当前连接及 Schema 一致。

| 编号 | 功能 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM4-01 | 对象树 | P0 | 按 Schema 展示受支持对象；懒加载、搜索、刷新；加载中、为空、无权限及失败分别显示 |
| DM4-02 | SQL Editor | P0 | 显示连接 / Schema，支持选区、当前语句和脚本执行；执行范围与服务端切分一致 |
| DM4-03 | Completion | P1 | 支持 Schema、表、视图、列、常用函数；识别当前 Schema 和别名；无权限对象不进入补全 |
| DM4-04 | Error Hint | P1 | 展示语法诊断和数据库原始错误；服务端位置可映射到编辑器；不确定位置不伪造精确定位 |
| DM4-05 | DDL Editor | P0 | 获取真实 DDL、编辑、预览变更、提交执行、回读验证；无法安全推导变更时要求用户提供 ALTER 等执行脚本 |
| DM4-06 | Data Editor | P0 | 分页、筛选、排序、插入、更新、删除；精度和 NULL 正确；无可靠行身份时禁止误改多行 |
| DM4-07 | ER Diagram | P1 | 根据真实 PK / FK 展示表及关系，支持复合键和跨 Schema 引用；权限外目标显示受限引用，不加载其详情 |
| DM4-08 | 能力与结果状态 | P0 | 不支持操作禁用并解释；分别显示提交、回滚、未执行、取消请求中和未知状态 |

数据编辑默认使用主键或可靠唯一键定位；支持乐观并发检查，避免覆盖其他会话的修改。没有稳定键时可限制编辑；允许强制多行操作必须明确展示目标条件及影响范围并重新确认。

DDL 编辑不得把“修改 CREATE 文本”自动等价为安全变更现有对象，不得默认通过删除再重建实现修改。执行前识别可能的数据丢失、对象依赖和非原子性，执行后刷新元数据。

阶段出口：对开发者和分析人员核心流程完成浏览器端到端验收；连接切换、失效元数据、权限变化、失败与重试等状态都有覆盖。

## 8. 第五阶段：Advanced SQL

### 8.1 目标

支持复杂脚本、存储程序和计划分析，并准确表达运行结果、事务边界和潜在副作用。

| 编号 | 功能 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM5-01 | Explain | P0 | 在认证版本获取估算计划；保留原始输出并转换为计划节点；取不到行数或成本时显示未知 |
| DM5-02 | 匿名块与嵌套程序块 | P0 | 完整发送单个块，保留源位置；SQL 编辑器和 Agent 使用相同切分结果 |
| DM5-03 | Procedure / Function 调用 | P0 | 按元数据绑定 IN / OUT / INOUT、返回值及支持的结果集；不支持参数类型执行前提示 |
| DM5-04 | Trigger 管理及执行关联 | P0 | 支持认证的启停与定义修改；DML 触发器错误定位到相关对象，不将触发器视为单独可调用过程 |
| DM5-05 | 多语句执行 | P0 | 按顺序执行，每条有状态、结果、耗时和消息；失败后行为取决于所选模式；结果顺序稳定 |
| DM5-06 | 取消、超时和资源限制 | P1 | 长查询 / 程序调用可申请取消；数据库终止状态与界面一致，无法确认时不宣称已回滚 |

Explain 默认只获取估算计划。任何实际执行 SQL 的分析模式须单独声明执行语义、权限和副作用，不得通过“查看计划”隐式执行写入。

程序内部提交、自治事务、动态 SQL 或外部副作用应列入风险分析；缺少充分信息时按未知副作用处理。批量执行在提交成功后才能标记已提交；失败且不能确认回滚时不能统一标成已回滚。

阶段出口：验证嵌套程序块、带 OUT 参数过程、返回值函数、触发器失败、多结果、批量中途失败及估算计划；以数据库实际状态核对执行响应。

## 9. 第六阶段：Agent

### 9.1 目标

Agent 能理解 DM 方言及作用域，在用户授权范围内发现对象、生成 SQL、解释风险并执行，保证模型建议与实际数据库操作之间有可审计的约束。

| 编号 | 功能 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DM6-01 | DM 上下文 | P0 | 包含连接、认证版本 / 能力、当前 Schema、可见对象及必要结构；不发送数据库密码 |
| DM6-02 | SQL 理解与对象提取 | P0 | 调用第三阶段分析；按当前 Schema 解析未限定名称；动态对象明确标记未知 |
| DM6-03 | 风险分类 | P0 | 综合语句类型、写对象、锁、调用与动态 SQL；无法判定时不降级为安全只读 |
| DM6-04 | 写操作审批 | P0 | 展示准确 SQL、目标连接 / Schema、对象和风险；授权与实际执行载荷绑定；内容变化后原审批失效 |
| DM6-05 | 执行与结果解释 | P0 | 复用统一权限和执行入口；如实报告提交、回滚、未执行及未知；不自动重试结果未知的写请求 |
| DM6-06 | 上下文更新 | P1 | 对象变更或权限变更后失效缓存；不能沿用旧会话中另一个连接的 Schema |
| DM6-07 | 回归评测 | P0 | 使用固定问题、SQL 及风险语料测评；全部越权、审批绕过和破坏性误执行用例通过 |

### 9.2 风险与审批规则

| 分类 | 示例特征 | 默认处理 |
| --- | --- | --- |
| 已确认只读 | 支持语法内且未发现写入、锁或未知调用 | 校验权限后可按工作区只读策略执行，受行数和超时限制 |
| 有限写入 | 明确目标及条件的 INSERT / UPDATE / DELETE / MERGE | 按已有有效写权限及审批策略执行，展示影响范围的确定性 |
| 结构或高影响操作 | DROP / TRUNCATE / ALTER、权限变更、无条件修改等 | 强化确认；不得将预估影响行数当作保证 |
| 未知副作用 | 动态 SQL、未解析语法、未知函数 / 过程调用 | 禁止自动执行，要求人工审查及显式授权，或拒绝不支持的执行 |

不能仅因 SQL 以 SELECT、WITH 或 EXPLAIN 开头就认定安全。对象不存在、对象不可见和解析失败应区分处理，不能让模型自行猜测并越权扩大搜索范围。

单次审批绑定用户、工作区、连接、Schema、SQL 和参数摘要、执行模式、有效期及一次性标识；明确授权的是当前展示的载荷。持续授权采用现有权限模型单独表达范围，不得由一次审批暗中升级而来。消费审批与执行状态登记需处理并发和重复请求。

阶段出口：端到端验证“自然语言 → 对象发现 → SQL 分析 → 风险展示 → 必要审批 → 执行 → 结果解释”，并覆盖 SQL 被篡改、过期审批、跨工作区、切换连接、重复提交和动态 SQL 场景。

## 10. 跨阶段接口与数据契约

以下是目标契约，命名和路由在接口设计评审中与现有 DTO 对齐，不代表已经存在相应字段。

| 契约 | 必要内容 |
| --- | --- |
| 能力描述 | 数据库类型、服务器 / 驱动版本、认证配置、功能列表、不支持原因 |
| 对象标识 | connectionId、schema、objectType、原始 name、可选父对象 |
| SQL 分析 | 方言版本、语句范围、解析状态、诊断、读写对象、调用和未知副作用 |
| 执行请求 | 连接作用域、SQL / 参数、执行模式、超时、结果限制、请求标识及需要时的审批引用 |
| 执行响应 | executionId、逐语句状态、执行耗时、结果、消息、事务结果和部分生效信息 |
| 错误 | 分类、原始数据库错误码 / SQLState、可映射的位置、是否可重试、是否存在未知执行结果 |
| 审计事件 | 操作者、工作区、作用域、载荷摘要、授权依据、执行及事务状态、关联标识 |

对于 `COMMITTED`、`ROLLED_BACK`、`FAILED`、`NOT_EXECUTED`、`CANCEL_REQUESTED`、`CANCELLED` 和 `UNKNOWN` 等状态，应避免单个 success 布尔值丢失信息；保留旧字段时明确映射规则并保持 API 兼容。

## 11. 非功能需求与认证策略

### 11.1 兼容性

建立发布认证表，至少记录 DM8 精确构建版本、驱动版本、JDK、操作系统 / 部署方式、字符集、兼容相关配置、大小写行为和测试账户权限。当前驱动默认值可作为首个候选，不自动等于官方支持全矩阵。

首个里程碑至少认证一个具体配置；后续版本仅对通过回归的组合声明支持。未认证组合允许以明确提示的试用方式连接，但不得在产品中承诺完整能力。涉及数据库行为的争议以对应版本官方资料及隔离实库验证为准。

### 11.2 性能与资源目标

以下为建议验收目标，需在需求评审中按部署资源冻结，尚非已有性能承诺。基准条件建议为同机房网络、固定测试数据、20 并发用户、每 Schema 1 万个对象、元数据单页 100 项，并分别记录冷缓存和热缓存。

| 指标 | 建议目标 | 测量边界 |
| --- | --- | --- |
| 元数据单页加载 | p95 ≤ 2 秒 | 含数据库字典查询，不含首次驱动下载 |
| 本地补全 | p95 ≤ 300 毫秒 | 已有元数据缓存，不含首次对象发现 |
| SQL 语法分析 | 100 KB 认证脚本 p95 ≤ 500 毫秒 | 服务端解析时间，不含模型调用和数据库执行 |
| 取消请求受理 | ≤ 1 秒 | 受理不代表数据库已终止；后续状态需持续追踪 |
| 稳定性 | 1 小时并发测试无持续连接 / 内存增长 | 包含连接失败、超时、取消和池回收 |

长脚本、超大结果、LOB 及并发量均需配置上限；阈值命中必须可见。性能测试不能以删减元数据、截断而不提示或跳过权限检查达标。

### 11.3 安全与可观测性

连接凭据采用项目统一的加密存储与脱敏策略。元数据名称、表注释和数据库结果均按非可信内容处理，不可成为覆盖 Agent 权限或执行策略的指令。

所有用户、Agent、批量、取消和对象管理入口均执行相同的所有权与工作区权限校验。取消只能操作授权范围内的执行任务。日志默认记录 SQL 摘要，完整 SQL 和结果按敏感数据策略控制；不得记录驱动连接密码。

需记录连接创建 / 归还、池耗尽、SQL 执行、提交 / 回滚、取消、解析失败及审批事件，并用 executionId 等标识关联。失败应可定位到阶段和对象，而不要求用户阅读服务器内部实现。

## 12. 测试、验收与发布

### 12.1 测试层次

| 层次 | 核心覆盖 | 验收证据 |
| --- | --- | --- |
| 单元测试 | 名称引用、类型分派、切分、解析、风险、状态转换 | 自动化报告及输入输出语料 |
| SPI / 服务契约 | 能力声明、权限、错误与状态映射、插件兼容 | DM 与现有数据库插件契约测试 |
| DM8 实库集成 | 字典、DDL、数据往返、事务、调用、Explain | 精确版本与配置、隔离夹具、数据库状态断言 |
| 浏览器 E2E | 连接、对象树、SQL、DDL、数据、ER、失败恢复 | 核心流程报告和必要截图 |
| Agent 评测 | 对象作用域、生成 SQL、风险、授权、执行解释 | 固定问题集、执行载荷和授权记录 |
| 非功能测试 | 大量对象、并发、取消、超时、敏感数据、越权 | 性能与故障测试报告 |

实库测试使用专属数据库或 Schema 和唯一运行前缀；禁止以固定对象名先 DROP 再 CREATE 的方式在共享业务库进行验收。清理只针对本次测试创建的对象；测试失败必须保留可诊断日志。

### 12.2 核心验收用例

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| AT-01 | 使用不可访问 Schema 建连，多次重试 | 无物理连接泄漏，错误可定位 |
| AT-02 | 同时访问两个 Schema 的同名表 | 查询、补全和 Agent 均选择正确对象 |
| AT-03 | 两条可事务化 DML，第二条失败 | 第一条回滚，失败与未执行状态准确 |
| AT-04 | DDL 与 DML 混合并中途失败 | 按所选模式拒绝或准确显示部分生效，不虚报全部回滚 |
| AT-05 | 高精度数值、时区、NULL、Unicode、LOB 往返 | 无静默精度损失、乱码或截断写回 |
| AT-06 | 带大小写、引号、分号的对象名称 | 浏览、DDL、切分及数据修改一致正确 |
| AT-07 | 各对象 DDL 在空白 Schema 重建 | 支持属性的语义一致，未覆盖属性明确提示 |
| AT-08 | 复合外键及跨 Schema 关系 | 元数据、ER 和 Agent 对应顺序一致 |
| AT-09 | 程序块、函数、触发器混合脚本 | 分隔符处理正确，逐语句位置与结果准确 |
| AT-10 | 无效 SQL 与未支持语法 | 分别报告错误或不支持，不返回验证通过 |
| AT-11 | 查询中含未知调用、动态 SQL | 不自动判定安全只读，不绕过审批 |
| AT-12 | 审批后修改 SQL 或切换连接 | 原审批不能授权新载荷 |
| AT-13 | 执行超时、取消或提交时断网 | 状态与可确认事实一致，不自动重复写入 |
| AT-14 | 普通账户对象发现与详情读取 | 可见对象正确，无权限不冒充空对象 |
| AT-15 | 回归 MySQL 工作台及 Agent | 共享服务和 SPI 变更不破坏既有行为 |

### 12.3 发布门禁

每个阶段提交需求覆盖表、实现清单、测试报告、认证矩阵、已知限制与回退方案。P0 全部通过且无数据损坏、越权、误执行等阻断问题后，方可发布该阶段能力；六阶段完整发布还要求所有 P1 验收通过。

阶段性功能通过能力开关开放。发现方言或风险分析回归时，可关闭对应高级功能或 Agent 自动执行，保留已认证的基础浏览功能。应用回退不等于数据库变更回退，不得承诺已执行 DDL 可自动撤销。

| Agent 将未知语句视为安全 | 服务器保守判定并绑定审批载荷 | M6 |
| 大规模对象造成树和上下文膨胀 | 分页、缓存、定向检索与上下文预算 | M2 / M6 |

评审需冻结的事项：首个 DM8 构建与驱动组合、必须认证的兼容配置、性能测试资源、语法支持清单、审计保留周期，以及既有持续授权策略对高影响操作是否要求二次确认。以上不阻碍基础实现设计，但必须在对应出口前形成可测试决策。
